# Agent OS：记忆方式与工作逻辑（通用）

> 来自傻妞资料包的元系统（SOUL / MEMORY / TOOLS / USER / recent_memory / LEARNINGS，2026-10-26），
> 以及当前 Agent 工程实践（Agent Skills 开放标准、AGENTS.md、长任务可暂停恢复）。
> 每个 Agent 都按这套跑。

## 一、记忆分层（四层，各有预算）
| 层 | 放什么 | 预算 | 谁来写 |
|---|---|---|---|
| 身份层 | 人设、语气、边界 | 2–3 KB | 建立时写死，改动需审批 |
| 规则层 | 硬规则、红线、项目规则 | 3–5 KB | 只追加，带日期与理由 |
| 经验层 | 踩坑、最佳实践（LRN 编号） | 不限条数，单条 ≤10 行 | 每次任务后按需追加 |
| 索引层 | 任务摘要 + 路径 + 标签 + 重要度 | 每条 ≤60 字 | 任务结束写一条 |

**原则**：身份层和规则层是"每次都读"的，所以必须短；经验层和索引层是"按需检索"的，所以可以多，但要有索引。

## 二、工作循环（每个任务固定五步）
1. **接单确认**：目标、人群/对象、输入、交付物、时间窗口。缺哪个问哪个，一次问完。
2. **查索引**：先读 `INDEX.md` / 知识索引，定位到 1–3 份相关文件，不整库倒进上下文。
3. **执行**：按该 Agent 的回复逻辑产出；每步产物是下一步的输入，不跳步。
4. **交付验收**：对照 `eval.md` 逐条自查；不达标说明差在哪。
5. **记台账**：值得复用的经验写 LEARNINGS；任务摘要写索引。

## 三、交付契约
- 每个交付物必须写清：**是什么、给谁用、怎么用、验收标准**。
- 长内容落文件；对话里只给结论 + 链接。
- 不承诺做不到的事；不确定标注置信度。

## 四、交接契约（Agent 之间）
上游必须给下游：目标、已确认的约束、产物路径、验收标准。
下游发现上游缺字段，**先退回补充**，不自行脑补。

## 五、复盘（每周一次）
- 三态跟踪：已解决 / 进行中 / 卡住（卡住要写卡点与下一步）。
- 只看三个数：产出量、返工率、客户/用户反馈。
- 复盘结论要落到规则或经验层，不能只写"下次注意"。

## 六、边界
- 不越权改全局规则（`rules.md` 的修改要人确认）。
- 不把客户隐私、密钥写进任何会外发的文件。
- 资料更新后，先更新知识文件，再改行为。
