# 09 · 教练助手系统（本地课序引擎）集成

> 对象：`D:\Downloads\普拉提`（Node 24 + 内置 `node:sqlite`，零依赖，本机 `127.0.0.1:7788`）
> 作用：门店排课、客户课序、课后双记录、复测、成长卡、课时包与结算。

## 一、它能提供什么

| 能力 | 数据来源 | Agent 怎么用 |
|---|---|---|
| 客户档案（34 字段） | `client` | 排课前先看：人群、主诉、红旗、可约时间、怕什么 |
| 课次链 | `session` + `class_record` | 看上一节实际做了什么、疼痛、疲劳、下次要改什么 |
| 客户反馈 | `client_feedback` | 看感受、强度、酸痛部位、原话 |
| 复测 | `retest` | 看阶段结论与下一阶段 |
| 课表 | `schedule` + `booking` | 看今天/本周谁要来、来没来 |
| 课时包 | `client_package` | 看剩几次、什么时候到期（续费时机） |
| 规则库 | `rule` | 安全/进阶/降阶/复测/剂量，共 6 条，带版本 |

## 二、读取方式（只读，不写库）

Agent 通过桥脚本取数：

```powershell
node D:\Downloads\普拉提\app\agent-bridge.js list
node D:\Downloads\普拉提\app\agent-bridge.js client 3       # 或用化名
node D:\Downloads\普拉提\app\agent-bridge.js client 李姐
node D:\Downloads\普拉提\app\agent-bridge.js today
node D:\Downloads\普拉提\app\agent-bridge.js week
node D:\Downloads\普拉提\app\agent-bridge.js rules
```

输出为 JSON；`client` 会返回：档案 + 最近 6 节课（含记录与反馈）+ 最近 3 次复测 + 未来 5 次排课 + 课时包。

## 三、使用规则

1. **涉及具体客户或课表，先取数再回答**。不要凭记忆编客户情况。
2. 引用客户时用**化名 + id**（如「李姐 #1」），不写手机号尾号、不写真实姓名。
3. **只读**：不执行任何写库操作；排课、扣次、改档案由教练在 App 里做。
4. 给建议时对齐规则库：红旗命中只出降阶 + 转介；剂量按 `R-DOSE-01`；进阶/降阶按 `R-PROG-01` / `R-REG-01`。
5. 对外话术仍受 `rules.md` 约束（禁「修复/矫正/治疗/根治/保证」）。
6. 桥不可用（Node 版本低、路径变了）时，**明确告诉用户取数失败**，改为让用户贴关键信息，不要猜。

## 四、字段速查

`client`：alias, age, segment, complaints[], red_flags[], avail_fixed[], family_note, exercise_hist, equip_pref, balance, expire_on, last_visit, stage, churn_risk, price_sensitivity, support, referral_source

`session`：seq_no, stage, plan[], plan_source, status

`class_record`：actual[], completion{}, pain(0-10), pain_site, compensation[], fatigue(1-5), next_change, note

`client_feedback`：feel(难受/一般/很好), intensity(1-5), sore_parts[], voice_text

`retest`：round, date, metrics[], tests[], conclusion[], next_stage

## 五、典型用法

**排下一节课**
```
1. node app/agent-bridge.js client <id>
2. 看上一节：实际动作、疼痛、疲劳、next_change
3. 看反馈：感受与强度
4. 按规则库给 6–8 个动作 + 剂量，标注降阶/进阶依据
```

**课前 60 秒**
```
1. today 看今天名单
2. client <id> 看每人红旗与上次记录
3. 输出每人一句「今天注意什么」
```

**续费提醒**
```
1. client <id> 看 balance 与 expire_on
2. 结合最近到课与反馈，判断该不该提续费、怎么提
```

## 六、边界

- 这个系统是**教练的工具**，不是医疗诊断系统；红旗仍按 `rules.md` 转介。
- 数据只在本机（`data/studio.db`），**不外传、不截图发群**。
- 客户分享链接只读、可撤销；Agent 不生成也不修改分享 token。
